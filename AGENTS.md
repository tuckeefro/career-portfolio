# Career portfolio agent instructions

Scope: this repository, Tucker's complete work history, and its portfolio artifacts. User instructions and current permissions take precedence.

Read [the task brief](docs/AUTONOMY_BRIEF.md) and [the work queue](docs/WORK_QUEUE.md). Use existing [source review](docs/SOURCE_REVIEW.md), [evidence map](docs/EVIDENCE_MAP.md), [figure guide](docs/FIGURE_GUIDE.md), and [owner inputs](docs/OWNER_INPUTS.md). The brief is the portable specification; the queue is the only mutable execution state.

## Outcome

Make the portfolio useful to hiring teams assessing practical technical work. Optimize credible employment fit, safety, and supported likelihood. Deliver excellent technical graphics, inspectable evidence, natural writing, and supported discoverability.

Cover paid engineering, fabrication, practical operations, independent hardware/software/Linux/research, and university work. Keep Raw Creative, Tension Climbing, Maybell, Pouch Factory, DBC, and Mines visible without assigning unconfirmed work or dates. Aspirational specialties do not drive the default presentation.

## Work independently

- Inspect the whole coverage map before choosing a batch. Improve several relevant areas before deepening a single case.
- Complete reversible research, drafting, source tracing, drawings, checks, and authorized branch/PR work without asking for routine choices.
- Do not keep refining Pouch Factory or a favored specialty while other useful work remains. A new deep study must close an identified evidence gap.
- Search accessible records before asking Tucker to reconstruct them. After three focused unsuccessful source searches for a detail, record the search and park that dependency; continue other work.
- Consolidate genuinely necessary firsthand questions, normally up to three at a checkpoint. Reuse parked questions and supplied answers. Missing details do not block unrelated work.
- Reconcile the current branch, open PR, and queue before writing. Continue the existing batch rather than opening competing PRs.
- Use native Codex task/Goal execution for the reasoning loop and existing GitHub Actions for verification. Do not introduce a custom paid/API-key scheduler.
- Follow actual task authorization for merging, publication, outreach, submissions, spending, and infrastructure. Repository permissions alone do not establish authorization. A branch in a public repo is public; publish only material appropriate for this portfolio.

## Evidence and decision writing

Recover the full account before making the short version: responsibility, interacting constraints, actual alternatives, chosen arrangement, downside/accepted tradeoffs, execution, check, result, and limit. Present supported judgment positively through those details.

Distinguish original records, firsthand recollection, functional reconstruction, illustrative calculations, retained synthetic execution, and measured results. Keep numbers, units, conditions, and sources together. Do not fill factual gaps with invented comparisons, interfaces, results, credentials, or chronology.

Preserve team contribution and accurate credit for agent-implemented software. Private employer documents/code and unrelated personal data do not belong in public commits.

## Voice

Use Tucker's practical Colorado cadence: direct, occasionally sideways or overbuilt, with an occasional bigger word and technical terminology where the work earns it. Keep the contribution and decision understandable.

Recruiter prose stays composed. Portfolio cases can retain individual rhythm and rough edges. Informal notes may use "man," "dude," or profanity when appropriate. Avoid caricature, invented outdoor stories, generic branding, gloating, and artificially manufactured mistakes.

## Graphics and discovery

Give each figure a technical question. Use accurate annotated hardware/CAD views, schematics, diagnostic comparisons, retained-data plots, and source-linked captions. Preserve editable sources and regenerate affected exports together.

Inspect changed graphics at full size, phone width, and print/PDF where applicable. A successful export/check is not visual approval. Existing PNG files can be inspected through the GitHub file connector with base64 encoding when local preview is unavailable; inspect actual generated previews when available.

Use descriptive headings, opening text, captions, links, and supported skill terms. GitHub Markdown is the current surface; HTML metadata, canonical URLs, and indexing require an established published site. Do not claim search rankings or numerical hiring odds.

## Checks and completion

Read complete affected files and dependencies. Review the diff for facts/contribution/scope, then implementation, links, rendering, and quoting where applicable.

Run the commands in the brief on the actual candidate. Use fresh CI evidence for the exact candidate SHA when local execution fails. Report checks and visual observations separately. A launcher failure is an execution limitation, not a portfolio or workstation-health finding.

A batch ends with a reviewable diff, actual validation evidence, a concise report, an updated queue, and one next action. Do not declare the whole release finished while required ready work remains.
